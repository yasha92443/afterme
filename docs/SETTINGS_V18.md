# AfterMe 设置与 schema 18

每人独立部署 Cloudflare Worker 与 D1，使用自己的邮箱、密钥和配置。寄信与核验路径由部署者选择；套餐与账单由部署者在服务商管理。

## 设置怎么生效

首页用于本人签到、下一次行动与待处理事项。设置页分为基本与高级项。提醒时间按最后一次计时起点累计，必须递增，使用整数小时，范围 1–8760 小时；缓冲范围 0–8760 小时。可选择小时／天，推荐值如下：

| 预设 | 本人提醒 | 联系人提醒 | 开始核验 | 默认缓冲 |
| --- | ---: | ---: | ---: | ---: |
| 较短 | 24h | 48h | 96h | 72h |
| 当前默认 | 48h | 72h | 120h | 72h |
| 较长 | 72h | 120h | 168h | 168h |

私人、公开通道各自选择确认人、人数和缓冲。允许一人确认与零缓冲；页面明确显示后果。确认人数保持设置值，联系人不足时暂停释放。公开网页与公开 PDF 可分别关闭，PDF 收件名单与确认名单相互独立。私人信件沿用每封信的收件人和撤回功能。

两通道可以选择同一批确认人，同一人同一轮只需确认一次；私人确认名单由所有私人信件共用。私人正文按每封信的收件安排交付。人员录入与语言设置统一放在 [人员目录](PEOPLE_DIRECTORY.md)，实际用途仍在规则或每封信里选择。

保存释放规则只产生待生效版本，只有下次本人签到才采用。正在核验或缓冲时，数据库、后台、页面和邮件继续读取本轮冻结的规则。主题、语言、字号、PDF 样式、本人资料、联系人语言与维护偏好可直接保存；释放规则仍在下次本人签到时采用。PDF 外观更新沿用原投递回执。

公开和私人释放分别推进；一类已释放，另一类仍可核验。本人签到或有效误报取消整个轮次并撤回网页、私人链接。已送出的邮件附件无法撤回。

旅行暂停会取消确认和缓冲，阻止失联提醒、核验与释放。自动恢复以到期时刻为新计时起点；手动恢复等待本人签到。自动恢复和误报保留实际本人签到记录与本轮规则；待生效规则由本人下次签到采用。离线到期输入按设置页所选时区解释，数据库保存 UTC。

示例 Cron 每 5 分钟分批推进一次，实际频率以部署配置为准；零缓冲表示确认条件满足后即可进入投递，实际处理时间还取决于调度与邮件服务。Gmail 积压、收信失败或待处理核验回复会阻止释放，直到故障恢复。单人确认仍要求同样的真实来源与轮次验证。

## 界面与文字

主界面支持中文、英文、俄文，夜读、纸页、高对比及跟随系统；语言和主题切换保留章节、滚动位置和未保存输入。PDF 单独选择夜读或纸页样式。正文保留原文。人员目录统一管理确认人和收件人；明确修改某人的邮件语言会同步其两个用途。升级时保留旧资料各自的名字、语言和启停状态，存在差异时由本人选择后再统一。

联系人邮件回复必须在第一行使用核验邮件提供的一条完整指令。系统按当前轮次校验明确且唯一的有效指令。网页核验使用相同的三个内部状态。

默认邮件采用动态时间、人数和缓冲占位符。自定义文案保留原文，维护页提醒检查过时的固定时间。高级编辑、排序、回收站及法律遗嘱位置记录保留在“完整编辑工具”入口。

## API 与安全

- `GET /api/settings`：修订号、当前／待生效规则版本、偏好、本轮快照与双通道进度。
- `PUT /api/settings`：必须携带 `revision`、完整 `preferences`、`rules`；可附本人资料与联系人语言。冲突返回 409，整次写入保留原状态。
- `POST /api/settings/preview`：返回时间线、人数与额度的模拟结果。
- `POST /api/pause`：`mode=automatic|manual`、UTC `until`；`POST /api/resume` 表示本人签到恢复。
- 目录、章节、条目与日志采用游标分页，默认 50、最大 100。`GET /api/items/:id/content` 才解密选中的私人正文。
- `POST /api/session` 签发 30 分钟 HttpOnly Cookie，`POST /api/logout` 撤销会话。Cookie 写操作要求 CSRF 与同源检查，保留 Bearer API。旧页面过期后重新登录。
- 降低确认人数、缩短缓冲和完整备份要求五分钟内验证口令。实际请求体读取字节限制为登录 8 KiB、普通写入 256 KiB。
- 新写入强制独立内容密钥，历史密文保留兼容读取。日志不记录口令、令牌或信件正文。

Cloudflare 原生限流用于登录、核验、高开销入口、普通 API 及阅读／健康检查；准确的全局投递额度由 D1 原子领取控制。五个绑定缺失时拒绝对应请求，开发 fallback 必须显式启用且不得用于部署。D1 原子邮件领取、去重、每日额度及结果不明时人工核对继续保留。[Cloudflare 官方说明](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

## PDF 与测量

schema 22 引入默认浏览器后台准备 PDF。正文保存独立于准备状态，缺失、过时或损坏的文件需要在已认证管理页准备／重试；关闭页面后重新登录可继续。按内容、正式版本及排版／语言／时区信息核对文件，分块校验后才标记就绪。默认模式由浏览器准备 PDF，Cron 读取校验就绪的文件。旧执行模式的公开 PDF 源数据预检上限为 4 MiB、单份准备 PDF 默认上限为 8 MiB；分阶段模式的分页与验收容量见 [PDF 流程](PDF_ATTACHMENTS.md)。

私人正文在打开信件时按需读取，保存后刷新对应区域。响应提供 `Server-Timing`、SQL 语句数、数据库 round trip 和读取行数；批次调用与语句数应分别记录。`db` 为重叠等待去重后的数据库墙钟时间，`db_total` 为累计等待，分别表示数据库等待时间。CPU 时间在 Cloudflare 实例中单独测量，详见 [指标说明](NAVIGATION_PERFORMANCE.md)。

## 独立部署与恢复

Windows、macOS、Linux 均运行 `npm run setup:guided`。`npm run setup:guided -- --check` 检查本地配置。Worker 运行程序和验证网页，D1 保存内容和全局额度；示例 Cron 每五分钟有预算地推进一批工作，Gmail 或 Resend 负责寄信。保留 `nodejs_compat` 和构建后的浏览器资源。

寄信与核验收信独立选择：Gmail 或 Resend 寄信；专用 Gmail 回复或 HTTPS 验证网页。Resend 必须明确配置核验路径及所需凭据，缺失时拒绝运行；套餐、域名与额度由使用者选择，在服务商完成购买或升级。

Gmail 需要 OAuth 三项 secret。外部应用处于 Testing 且使用 Gmail scope 时，刷新令牌可能七天过期。授权失效会阻止释放；运行 `npm run gmail:oauth` 重新授权，再更新 Worker secret。[Google 官方说明](https://developers.google.com/identity/protocols/oauth2)

上线顺序：自动测试与隔离浏览器／PDF 验收（分阶段模式还须通过逐阶段 CPU 门槛）→ 完整生产备份和离线恢复验证 → 增量迁移至 0024 → 部署匹配代码及绑定 → 完成 PDF 准备并核对内容、本人状态、健康与自然 Cron。恢复工具兼容 schema 16–24，严格检查必要表、配置和应用读取，拒绝覆盖且默认冻结释放。真实签到记录保留，新的计时起点与轮次使旧核验／访问链接失效。HTTP 大型备份限制及离线转换见 [运维说明](OPERATIONS.md)。
