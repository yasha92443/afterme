## 已选择的容量与兼容边界

- 旧模式示例每五分钟推进一小批任务；schema 24 可选三条独立调度推进后台阶段，启用前需通过
  [逐阶段 CPU 验收](BACKGROUND_EXECUTION.md)。积压、额度和外部服务会延后进度。
- 默认浏览器准备 PDF，保留 `nodejs_compat`、字体绑定及五个原生限流绑定。
- 旧模式公开正式 PDF 源数据上限 4 MiB，单份准备文件默认上限 8 MiB；分阶段模式
  分页读取源数据，容量按实测配置，并检查完整 MIME 大小。该容量须分别通过 Cloudflare CPU、浏览器内存与邮件接收验收。
- 公开阅读及正式预览整页 HTML 上限 64 KiB，目录每页 20 章；标题、题辞、正文均有
  续读链接，版本变化要求从新版本重新阅读。打印功能打印当前阅读页，完整文档使用 PDF。
- 新完整导出为 schema 24／恢复格式 2；加密封套 2 使用 1 MiB 认证块，明文上限
  256 MiB。兼容恢复 schema 16–24 及旧加密封套 1。恢复丢弃派生任务、租约和远端
  上传会话，保留 canonical 发送／不确定回执。全量 JSON 和结果仍占内存。
- HTTP 全备份按当前数据估算约 16 MiB 的防御性预检；它不是流式导出，预检与快照
  存在增长窗口。较大实例使用完整 D1 导出及离线 `backup:from-d1` 转换／校验；SQL
  输入支持完整 schema 16–24 的字面量 dump，按可信迁移形状和已有迁移记录识别版本，
  不执行其中 SQL；只以有限 JavaScript 语法解码 D1 的 `replace`／`char(10或13)`
  换行包装，嵌套至多四层。混合版本、缺列和其他表达式会拒绝。
- 普通信件由服务端解密交付；已发附件无法撤回，口令信件仍需独立安排交付。
